# 常见问题

## bot 没有改名

确认当前人格启用了 `set_free_group_card`，模型支持工具调用，且聊天发生在 OneBot 接入的 QQ 群。插件只在已有模型请求中提醒，不会额外调用模型或在安静的群里启动任务。

提醒要求 bot 先使用改名工具，名字由 bot 自由决定。到期请求使用接口的强制工具调用选项；若模型仍只输出文字，本轮最多补一次明确请求，不会将未执行的回复草稿提前发送给群友或存入记忆。接口不支持强制调用时，补请求改用兼容方式。模型仍需具备工具调用能力，不能把无法调用工具的模型变成可用模型。

这项要求只作用于当前 Agent 中带有本次临时提醒的请求；改名工具调用后解除，正常回复、其他群、只读后台任务和记忆整理不会因此被强制改名。希望固定角色名时，填写可选的“基础名字”，插件会在实际提交时保留它。

小世界的自主发言还需要在其全局允许工具中加入 `set_free_group_card`，并开启主动工具。人格里启用该工具不会自动加入小世界的独立白名单；只读后台判断仍不会执行改名工具。

与小世界配合时，提醒在回复门禁之后执行。被拦下的模型请求不占用提醒间隔；已确认串门时暂停日常提醒，归家后恢复。

## 提醒间隔如何计算

每个 QQ 连接、机器人账号、群分别计时。模型实际开始处理提醒时开始计算间隔；之后若工具成功改名，起点更新为成功时刻。仅准备了请求、随后被取消或关闭，不计入间隔。

例如间隔为 10 分钟，15:00 收到提醒、15:02 改名成功，下一次提醒最早在 15:12 后的合格模型请求中出现。不是每条群消息重置计时，也不会在 15:12 自动调用模型。串门、工具不可用或改名失败冷却等条件仍会阻止提醒。

本轮补请求后仍没有调用工具时，日志会明确说明，并撤回这次未完成提醒占用的计时；一分钟后可在下一次合格请求中补提醒，不会重新等待整个配置间隔。正常成功改名仍按配置间隔计时。接口接受但尚未回读确认的请求也会重置间隔，避免立即重复写入。

准备后长时间没有开始的提醒，在后续模型请求到来时检查；超过两分钟便清理并恢复原工具，不必等一小时。模型正在处理的提醒不重复叠加。

## 如何看后台日志

搜索 `[随心名片]`，可以区分各个阶段：

| 日志 | 含义 |
| --- | --- |
| `已准备改名提醒` | 本轮已加入临时提醒，还没有开始计时 |
| `模型已开始处理改名提醒` | 模型进入本轮请求，开始计时 |
| `bot 已响应定期提醒并调用改名工具` | bot 实际调用了工具 |
| `接口强制调用` | 当前请求明确要求接口生成改名工具调用 |
| `本轮补一次明确提醒` | 模型只返回文字，尚未改名；最多补一次模型请求 |
| `当前接口不支持强制工具调用` | 使用兼容请求继续尝试，保持名字由 bot 决定 |
| `已恢复后续工具` | 首轮限制已解除，可继续原任务 |
| `改名成功，当前名片为…；QQ 回读已确认` | QQ 确认显示所选名片 |
| `名片已是所选内容，无需重复写入` | bot 选择了当前名片，核对后没有重复提交 |
| `QQ 接口已接受…但尚未回读确认` | 不能据此声称 QQ 已显示新名片 |
| `没有调用改名工具` | 本轮仍未调用，一分钟后可补提醒 |
| `请求在模型开始前结束` / `已清理未开始的旧提醒` | 本次准备没有执行，不占用间隔 |
| `暂不提醒改名` | 后面会说明间隔剩余时间、冷却、工具不可用或串门状态 |

同一群相同跳过原因最多每分钟记录一次；原因改变时立即记录。日志只说明改名流程，不输出聊天正文、完整人格或记忆内容。

改名首轮保留原请求中已有的会话历史、人格和记忆，只暂时优先提供改名工具。模型可以使用已经注入的上下文自由决定名字；需要另行调用工具检索的记忆，在改名后恢复工具时才可检索。插件不自行生成想法摘要或小世界处境提示。

## 基础名字与后缀

配置基础名字后，工具参数 `card` 表示后缀；留空配置时，`card` 表示完整名片。工具说明与提醒会告诉 bot 当前模式。即使关闭定期提醒，固定基础名字的规则仍然生效。

基础名字和后缀以一个空格连接，每次用新后缀替换旧后缀。工具传入空字符串可清除后缀，但只在配置了基础名字时允许。bot 若仍传入“基础名字 后缀”，插件会去掉开头重复的基础名字，避免拼接两遍。最终总长度超限时拒绝修改，原名片保留。

## 改名失败

查看同一时间的 AstrBot 与 OneBot 客户端日志。`1200` 是客户端执行失败的通用返回，不能仅凭它判断权限问题。确认机器人在线、可以修改自己的名片，并检查内容、长度和频率限制。

llbot + PMHQ 环境曾出现重启后机器人内部 UID 错配，导致底层 QQ 返回 `1013`。这种情况需要在客户端核对自身身份；插件无法替客户端修正登录信息。给机器人管理员权限不能解决身份错配。

每次工具调用最多提交一次写入，随后回读；不做连续写入重试。已生效但返回错误的请求，可通过回读确认成功。接口接受却无法回读时，仅报告未确认。

## 用哪个插件

随心名片是独立插件，工具名为 `set_free_group_card`，参数只有 `card`。可自由修改完整名片，也可填写基础名字后只修改后缀。没有模板、日程、系统指标、随机候选池、后缀有效期或定时任务。与原灵动名片一起使用时，应关闭其中一个插件的改名功能，避免互相覆盖。

## 验证范围

使用 AstrBot SDK 检查工具注册和真实 Hook 调度，通过模拟 OneBot 响应验证修改、超时、回读、并发及失败冷却。Windows 与 Linux 均运行回归测试；真实部署按 OneBot 回读确认结果。QQ 实际权限与限制以所用客户端和账号为准。
